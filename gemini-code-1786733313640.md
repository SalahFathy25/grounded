## 🛠️ Complete Technology Stack

### **Frontend (Client App)**
* **Framework:** React 18+ (scaffolded via Vite for maximum build speed)
* **Styling & UI:** Tailwind CSS (for modern utility-first responsive layout)
* **Icons:** Lucide-React
* **State Management:** React Context API / Zustand (managing Shopping Cart persistent state & Auth Context)
* **HTTP Client:** Axios (configured with Interceptors for JWT authorization header injections)
* **Routing:** React Router v6

### **Backend (Core Server)**
* **Language & Runtime:** Java 17 / 21 LTS
* **Framework:** Spring Boot 3.x
* **Security:** Spring Security (Stateless Architecture with JWT - JSON Web Tokens)
* **Persistence Layer:** Spring Data JPA + Hibernate
* **Build Automation:** Apache Maven
* **Boilerplate Reduction:** Project Lombok
* **DTO Mapping:** ModelMapper or MapStruct

### **Database & Infrastructure**
* **Database Management System:** PostgreSQL (Production) / MySQL
* **File & Image Hosting:** Cloudinary REST API / AWS S3 (for hosting uploaded product media)
* **Payment Gateways:** Paymob / Tap Payments API

## 🔌 Complete REST API Endpoints

### 🔐 Auth Module (`/api/v1/auth`)
* `POST /api/v1/auth/register` — Register a new user account.
* `POST /api/v1/auth/login` — Authenticate user, returns bearer JWT token and user info.

### 📦 Categories Module (`/api/v1/categories`)
* `GET /api/v1/categories` — Get all product categories.
* `POST /api/v1/categories` — **[ADMIN]** Create a new product category.
* `DELETE /api/v1/categories/{id}` — **[ADMIN]** Delete a category.

### 🏷️ Products Module (`/api/v1/products`)
* `GET /api/v1/products` — Retrieve paginated list of active products (Supports category filtering and keyword search).
* `GET /api/v1/products/{id}` — Fetch detailed product profile by ID.
* `POST /api/v1/products` — **[ADMIN]** Create new product (Handles Cloudinary image upload).
* `PUT /api/v1/products/{id}` — **[ADMIN]** Update product details, pricing, and stock.
* `DELETE /api/v1/products/{id}` — **[ADMIN]** Toggle product status (Soft Delete).

### 🛒 Order & Checkout Module (`/api/v1/orders`)
* `POST /api/v1/orders` — Submit new order from active user cart. Automatically reduces inventory stock.
* `GET /api/v1/orders/my-orders` — Get active customer's historical orders.
* `GET /api/v1/orders` — **[ADMIN]** Retrieve all orders across the system.
* `PATCH /api/v1/orders/{id}/status` — **[ADMIN]** Change order state (`PENDING` ➔ `SHIPPED` ➔ `DELIVERED`).

### 💳 Payment Integration (`/api/v1/payments`)
* `POST /api/v1/payments/checkout` — Generate checkout session payload for Payment Gateway.
* `POST /api/v1/payments/webhook` — Public endpoint receiving payment gateway webhook verification callbacks.

## 🎨 Frontend Application Architecture

### **Public / Customer Application (`/`)**
1. **Header / Navbar:** Sticky header with search input, category navigation, user profile trigger, and Cart Drawer indicator.
2. **Hero Landing Section:** Promotional slider and quick-featured category shortcuts.
3. **Product Catalog (`/products`):** Grid displaying product cards with image hover effects, price badges, and "Add to Cart" quick actions.
4. **Product Details Page (`/products/:id`):** Gallery view, detailed specifications, stock counter, and quantity selector.
5. **Slide-over Shopping Cart Drawer:** Fast access to cart adjustments, subtotal estimation, and checkout CTA.
6. **Checkout View (`/checkout`):** Address input forms, contact details, payment selection, and breakdown of order values.
7. **Order Success Confirmation:** Digital receipt view detailing ordered items and tracking ID.

### **Admin Dashboard Interface (`/admin`)**
1. **Dashboard Home:** Metrics dashboard displaying Total Revenue, Order Counts, and Low-stock inventory warnings.
2. **Product Catalog Management (`/admin/products`):** Interactive data-table listing products with quick edit, image update, stock adjustment, and deletion actions.
3. **Order Fulfillment Panel (`/admin/orders`):** Order review panel to filter orders by state and change shipment status.

## 🚀 Step-by-Step Implementation Roadmap

### **Phase 1: Backend Architecture Setup**
1. Generate Spring Boot boilerplate using `start.spring.io` with Web, Security, Data JPA, Lombok, and PostgreSQL driver.
2. Configure environment properties inside `application.yml` (Database URL, Credentials, Cloudinary Keys, JWT Secret Key).
3. Create JPA Models (`User`, `Category`, `Product`, `Order`, `OrderItem`).
4. Implement `UserRepository`, `ProductRepository`, `CategoryRepository`, and `OrderRepository`.
5. Configure `Spring Security` filter chain and write `JwtTokenProvider` & `JwtAuthenticationFilter`.
6. Construct Service interfaces and implementations for Products, Orders, and Payment integrations.
7. Write Controllers exposing RESTful JSON endpoints. Test via Postman.

### **Phase 2: Frontend Architecture Setup**
1. Initialize Vite React Application (`npm create vite@latest frontend -- --template react`).
2. Install dependencies (`tailwindcss`, `lucide-react`, `axios`, `react-router-dom`).
3. Set up Axios global interceptor to automatically add `Authorization: Bearer <token>` to request headers.
4. Setup Auth Context and Cart Context to handle global frontend state.
5. Build re-usable UI components (Navbar, Footer, Product Card, Loading Skeleton, Modal).
6. Build routes and views for Storefront pages.
7. Build Protected Routes for the Admin Panel (`/admin/*`) restricted to users with `ROLE_ADMIN`.

### **Phase 3: Integration & Testing**
1. Connect React forms and catalog to Spring Boot APIs.
2. Verify payment workflow end-to-end (Order Creation ➔ Gateway Redirect ➔ Webhook Callback ➔ Order Status Update).
3. Conduct error-handling and authorization checks (e.g., non-admin users blocked from admin endpoints).

### **Phase 4: Deployment & Domain Configuration**
1. **Backend Deployment:** Deploy Spring Boot JAR and PostgreSQL DB to cloud platforms (e.g., Railway, Render, or AWS EC2/RDS).
2. **Frontend Deployment:** Deploy Vite React build artifacts to Vercel or Netlify.
3. **CORS Setup:** Configure Spring Boot CORS mapping to accept requests exclusively from the production frontend URL.
4. **Custom Domain:** Point custom DNS (Domain Name) CNAME/A records to Vercel.
